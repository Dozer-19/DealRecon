# V3 campaign approval checkpoint

CampaignControl is a server-side domain service. It reserves campaign maximum costs against one combined $45 monthly ledger in a serializable transaction. New storage starts paused. Only the configured owner can submit, approve, pause, or cancel. Approval binds the exact reviewed snapshot; repeats do not reserve twice. Canceling an approved, undispatched campaign releases its reservation once. Requests cannot override server-configured quoted rates or ledger balances.

This checkpoint does not send calls or postcards and is connected to the Android review UI. Tests use a rollback-capable memory storage double. The communications-worker includes Firebase-authenticated review routes and a Cloudflare Durable Object adapter, but has not been deployed or tested on Cloudflare. The actor UID comes from a verified token, never the request body. Recipients, suppression state and consent evidence must be loaded from authoritative server records before live execution; review flags supplied by clients are not sufficient. Configure current all-in quotes on the server, including provider minimums, taxes and recurring fees.

Remaining integration: staging deployment and storage verification, provider sandbox adapters, and delivery webhooks with idempotency and actual-cost settlement. Before adding dispatch, introduce a dispatch state so cancellation cannot release funds already committed to providers. Recheck suppression, consent, pause, current billing month and approval immediately before dispatch. Reserve recurring fees independently so canceled campaigns cannot erase recurring liabilities. There is deliberately no live-execution switch in this module.

The separate communications-worker/wrangler.toml targets deal-recon-campaigns-v3 with nodejs_compat for the review fingerprint. Required server configuration: CAMPAIGN_OWNER_UID (Firebase UID) and CAMPAIGN_QUOTED_RATES (JSON with fixedMonthlyCents, postcardAllInCents, callAllInMinuteCents and maxCallSeconds). Missing owner, binding, or quotes fails closed. POST routes: /status, /submit, /approve, /cancel, /pause. /approve requires campaignId and the reviewed fingerprint; /pause accepts a boolean paused value. All routes require a valid deal-recon Firebase ID token and exact owner match. Private object access uses one workspace ID. No production deploy workflow has been changed.

Validation: campaign-control.test.mjs checks owner access, default pause, concurrent budget reservations, request rate tampering, duplicate approvals, revision invalidation and repeated cancellation. It runs before the Android build in GitHub Actions. Production main and signing configuration remain unchanged.

## Android 3.0.5-dev review screen

The Communications tab prepares one postcard for the selected lead and campaign. Confirm the destination, submit it, and review both postcard sides, recipients, exclusions, maximum cost and monthly reservations before approving the exact server snapshot. No AI calls are requested from this form. Pausing prevents approvals. Connection failures remove stale approval controls, with no local approval fallback. The fixed client URL is https://deal-recon-campaigns-v3.dealrecon.workers.dev; it is not deployed yet, so server actions are unavailable until staging setup is complete. Client tests verify authentication and fail-closed responses; UI tests verify paused approvals, exact snapshots, plain-text previews and destination confirmation. Existing local campaigns, letters and manual outreach are preserved.

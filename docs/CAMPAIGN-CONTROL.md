# V3 campaign approval checkpoint

CampaignControl is a server-side domain service. It reserves campaign maximum costs against one combined $45 monthly ledger in a serializable transaction. New storage starts paused. Only the configured owner can submit, approve, pause, or cancel. Approval binds the exact reviewed snapshot; repeats do not reserve twice. Canceling an approved, undispatched campaign releases its reservation once. Requests cannot override server-configured quoted rates or ledger balances.

This checkpoint does not send calls or postcards and is not connected to the Android UI. Tests use a rollback-capable memory storage double. The service requires a production transactional storage adapter and authenticated routes before deployment. The actor UID must come from a verified token, never the request body. Recipients, suppression state and consent evidence must be loaded from authoritative server records; review flags supplied by clients are not sufficient for live execution. Configure current all-in quotes on the server, including provider minimums, taxes and recurring fees.

Remaining integration: durable storage, authenticated review routes, app review screen, provider sandbox adapters, and delivery webhooks with idempotency and actual-cost settlement. Before adding dispatch, introduce a dispatch state so cancellation cannot release funds already committed to providers. Recheck suppression, consent, pause, current billing month and approval immediately before dispatch. Reserve recurring fees independently so canceled campaigns cannot erase recurring liabilities. There is deliberately no live-execution switch in this module.

Validation: campaign-control.test.mjs checks owner access, default pause, concurrent budget reservations, request rate tampering, duplicate approvals, revision invalidation and repeated cancellation. It runs before the Android build in GitHub Actions. Production main and signing configuration remain unchanged.
